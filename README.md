# ミームコイン候補スキャナー(Solana・読み取り専用)

15分おきに Solana のミームコイン候補を自動で探し、5段階で判定して Slack に通知します。
**売買の機能はありません。ウォレットの秘密鍵も使いません。** 買う・売るはこれまで通り Phantom で手動です。

---

## 全体の流れ

```
[GitHub Actions が15分おきに起動]
   │
   ├─ 候補を集める
   │    ・DEX Screener(新着プロフィール / CTO / ブースト)… 卒業済み = A
   │    ・Solana Tracker(pump.fun 卒業前・進捗50〜95%)   … 卒業前   = B
   │
   ├─ 審査する
   │    ・RugCheck      : 権限・危険な拡張機能・rugged・上位保有者・インサイダー・LP・開発者の詐欺履歴・送金手数料
   │    ・Solana Tracker: バンドル率・スナイパー率・開発者の保有率・保有者数・LP焼却率
   │    ・DEX Screener  : 流動性・時価総額・値動き・出来高・SNS・広告(ブースト / orders API)
   │
   ├─ 5段階で判定
   │    除外 → 記録のみ
   │    見送り → 記録 + 1日1回まとめて通知
   │    候補(リスク小 🟢 / 中 🟡 / 大 🔴)→ 毎回通知
   │
   └─ data フォルダに記録(CSV)して保存
```

### 使うデータ源と、選んだ理由

| 用途 | 使うもの | 料金 | 理由 |
|---|---|---|---|
| 卒業済みの新着 | DEX Screener API | 無料・キー不要 | 1分60〜300回まで使える公式API |
| pump.fun 卒業前(進捗%) | **Solana Tracker Data API** | 無料プランあり(要キー) | 進捗%・時価総額・保有者数で絞り込める専用の口がある |
| バンドル率・スナイパー率 | **Solana Tracker Data API**(同じキー) | 同上 | RugCheck にない項目が1回の呼び出しでまとめて取れる |
| 安全性の審査 | RugCheck API | 無料・キー不要 | ご指定どおり |
| 広告の有無 | DEX Screener orders API | 無料・キー不要 | ご指定どおり |

**ほかの方法を選ばなかった理由**
- **pump.fun の公式サイト用API**:公開された API ではなく、予告なく変わったりブロックされたりします。
- **Moralis**:pump.fun 用のエンドポイント(new / bonding / graduated)は 2026年7月31日に廃止されました。
- **Bitquery**:無料はお試しポイントだけで、毎月の無料枠がありません。

## ステップ1:Slack で通知の受け取り口を作る

### 1-1. 通知用のチャンネルを作る
1. Slack を開き、左のメニューで「チャンネル」の横の **＋** →「チャンネルを作成する」
2. 名前を `meme-alerts` にして作成(公開でも非公開でもOK)

> Slack のワークスペースをまだ持っていない場合は、https://slack.com/get-started から無料で作れます。

### 1-2. Webhook URL(通知を送るための専用アドレス)を作る
1. ブラウザで https://api.slack.com/apps を開き、右上の **Create New App** を押す
2. **From scratch** を選ぶ
3. App Name に `meme-scanner`、ワークスペースに自分のワークスペースを選んで **Create App**
4. 左のメニューから **Incoming Webhooks** を開き、右上のスイッチを **On** にする
5. 下の方の **Add New Webhook to Workspace**(または Add New Webhook)を押す
6. 投稿先に `#meme-alerts` を選んで **許可する**
7. 表示された `https://hooks.slack.com/services/...` で始まる URL の **Copy** を押す
8. メモ帳に一時的に貼っておく(ステップ4で使います)

> ⚠ この URL を知っている人は誰でもこのチャンネルに投稿できます。SNS やチャットに貼らないでください。

## ステップ2:Solana Tracker の API キーを取る

1. https://www.solanatracker.io/data-api を開く
2. 右上の Sign in / Get API key からアカウントを作る(Google ログインなどでOK)
3. ダッシュボードの Data API で **Free** プランを選ぶ(クレジットカード不要)
4. 表示された **API Key** をコピーして、メモ帳に貼っておく

### 無料枠の確認(大事)
Solana Tracker の無料枠は、公式ページによって「月10,000回」「月2,500回」と表記が分かれています。
**ダッシュボードに表示される自分の上限**を確認して、`config.yaml` の `monthly_budget` を合わせてください。

| ダッシュボードの上限 | config.yaml の設定 |
|---|---|
| 月10,000回 | そのままでOK(`monthly_budget: 9000`、`every_n_runs: 1`) |
| 月2,500回 | `monthly_budget: 2300`、pump.fun の `every_n_runs: 3`(45分おきに取得)、`st_cache_minutes: 180` |

月の上限は日割りで管理されます(`daily_pacing`)。月初に使い切ることはなく、その日の分に達すると自動で Solana Tracker を使うのを止めます(その月は pump.fun 卒業前の取得とバンドル率の審査が止まり、該当銘柄は「見送り」になります)。

## ステップ3:GitHub にプログラムを置く

### 3-1. リポジトリ(プログラムを置く箱)を作る
1. https://github.com にログイン(アカウントがなければ Sign up で作成)
2. 右上の **＋** → **New repository**
3. Repository name に `meme-scanner`
4. **Public(公開)** を選ぶ ← 理由は下の「公開・非公開の違い」を参照
5. **Create repository** を押す

#### 公開・非公開の違い
| | Public(おすすめ) | Private |
|---|---|---|
| GitHub Actions の料金 | **無制限で無料** | 月2,000分まで無料 |
| 15分おきに動かせるか | ◯ | ✕(月約2,900分かかり無料枠を超える) |
| 他人から見えるもの | プログラムと data フォルダの記録(銘柄名・判定) | 見えない |
| API キー・Webhook URL | **見えない**(Secrets に保存するため) | 見えない |

記録を他人に見られたくない場合は Private にして、`.github/workflows/scan.yml` の
`cron: "7,22,37,52 * * * *"` を `cron: "7,37 * * * *"`(30分おき・月約1,500分)に変えてください。

### 3-2. ファイルをアップロードする
1. 作ったリポジトリの画面で **uploading an existing file** のリンク(または **Add file → Upload files**)を押す
2. 受け取った `meme-scanner` フォルダの中身から、次のファイルをドラッグ&ドロップ
   - `scanner.py`
   - `config.yaml`
   - `requirements.txt`
   - `README.md`
3. 下の **Commit changes** を押す

### 3-3. 自動実行の設定ファイルを作る
`.github` フォルダは名前が「.」で始まるため、パソコンによっては見えずアップロードできないことがあります。
確実な方法として、ブラウザ上で作ります。

1. リポジトリの画面で **Add file → Create new file**
2. ファイル名の欄に、次の文字をそのまま入力する(「/」を打つとフォルダが自動で作られます)
   ```
   .github/workflows/scan.yml
   ```
3. 受け取った `scan.yml` をメモ帳などで開き、中身を全部コピーして大きな入力欄に貼り付ける
4. **Commit changes...** → もう一度 **Commit changes** を押す

### 3-4. 記録用のフォルダを作る
1. **Add file → Create new file**
2. ファイル名に `data/.gitkeep` と入力(中身は空のまま)
3. **Commit changes** を押す

## ステップ4:API キーを GitHub Secrets に保存する

Secrets(シークレット)は、パスワード類を暗号化して保存する場所です。保存後は自分でも中身を見られず、公開リポジトリでも他人には見えません。

1. リポジトリの上のタブから **Settings**(歯車)を開く
2. 左のメニューで **Secrets and variables → Actions**
3. **New repository secret** を押して、1つ目を登録
   - Name: `SLACK_WEBHOOK_URL`
   - Secret: ステップ1でコピーした `https://hooks.slack.com/...`
   - **Add secret**
4. もう一度 **New repository secret** を押して、2つ目を登録
   - Name: `SOLANATRACKER_API_KEY`
   - Secret: ステップ2でコピーした API キー
   - **Add secret**

> Name は1文字でも違うと読み込まれません。大文字・アンダーバー(_)まで正確に入力してください。

### 書き込み許可の確認
1. **Settings → Actions → General** を開く
2. 一番下の **Workflow permissions** が **Read and write permissions** になっているか確認(なっていなければ選んで **Save**)

## ステップ5:動作テスト(3段階)

### 5-1. Slack にテスト通知を送る
1. リポジトリ上のタブ **Actions** を開く
   (「Workflows aren't being run…」などと出たら **I understand my workflows, go ahead and enable them** を押す)
2. 左の **meme-scanner** を選ぶ
3. 右の **Run workflow** → mode で **test_slack** を選んで緑の **Run workflow**
4. 1分ほどで Slack に「✅ テスト通知です」が届けば成功

届かないとき:実行結果をクリック → `scan` → `Run scanner` を開いてエラーを確認。多くは Secret 名の打ち間違いです。

1. 同じ手順で mode に **dry_run** を選んで実行
2. 実行結果 → `scan` → `Run scanner` を開くと、判定結果や「Slack に送る予定の文面」が表示されます

### 5-3. 本番
- 何もしなくても、15分おきに自動で動き始めます
- すぐ試したいときは mode **normal** で Run workflow

## 通知の見方

**候補(毎回)**
```
🟡 候補(リスク中) 合計4点 — ABC
ABC Coin (ABC) ｜ B pump.fun卒業前 ｜ 卒業進捗: 72.0%
`アドレス全文`
⚠️ 便乗の疑い(有名銘柄と同じシンボル)   ← RugCheck の copycat 警告があるときだけ
テーマ(参考・点数外): 猫・AI
経過: 3時間 ｜ 時価総額: $31,000 ｜ 流動性: $20,500
値動き: 5分 +2.0% ｜ 1時間 +10.0% ｜ 6時間 +50.0%
バンドル: 10.0% ｜ 上位10件: 22.0% ｜ 開発者: 1.0% ｜ 保有者: 300人
点数の内訳
• 発行から1時間〜6時間: +1
• pump.fun卒業前: +2
• 流動性$15,000〜$30,000: +1
🧪 仮想売買: $20 分を仮想購入(実際の売買はしません)
DEX Screener ｜ GMGN ｜ RugCheck ｜ pump.fun
```
- **テーマ**は銘柄名・シンボル・説明文の単語から機械的に判定した参考情報で、点数には入りません。判定に使う単語は `config.yaml` の `themes:` で追加・変更できます
- 左の色帯:🟢 緑=リスク小(0〜2点)/ 🟡 黄=リスク中(3〜5点)/ 🔴 赤=リスク大(6点以上)
- 同じ銘柄は24時間は再通知しません。ただし段階が変わったら「(段階変更: 中→大)」付きで再通知します

**1日のまとめ(毎日21時ごろ)**
- 候補・見送り・除外の銘柄数、見送りの主な理由
- 段階ごとの成績(通知から1時間・6時間・24時間後の平均の値動きと、上がった割合)
- 仮想売買の成績(期間中・累計・段階ごとの件数、勝率、損益合計、決済理由)
- API の呼び出し回数と、Solana Tracker の今月の使用回数

**除外になる条件**(通知せず記録のみ)
- アドレスの末尾が `pump` でなく、RugCheck の発行元(launchpad)も Pump.Fun でない
  - 末尾が `pump` なら、この条件は通過
  - 末尾が違っても、発行元が Pump.Fun なら通過(例:FROGE `6R1F…375R`)
  - 発行元が Pump.Fun 以外と分かった銘柄は、7日間は調べ直しません(API の節約)
- 追加発行の権限・凍結権限が残っている / 危険な拡張機能 / rugged 判定
- RugCheck の警告に「Creator history of rugged tokens(開発者のラグ歴)」「Fee config enabled(手数料を変更できる設定)」がある
  - 警告の文字で除外を増やしたいときは `config.yaml` の `exclude_risk_keywords:` に追加できます

## 仮想売買(ペーパートレード)

候補を通知した時点で $20 買ったことにして、次のルールで損益を計算します。**実際の売買は一切しません。**

| ルール | 内容 |
|---|---|
| 損切り | 購入価格から −40% 以下になったら残りを全部売る |
| 利確1 | +50% 以上で最初の数量の半分を売る |
| 利確2 | +100% 以上で残りを全部売る |
| 時間撤退 | 購入から1時間たったら残りを全部売る |
| 手数料など | 1回の売買ごとに 1% を差し引く(`fee_pct`。0 にすると無視) |

- 価格の確認は15分おきの実行のたびなので、実際の値動きの途中(たとえば一瞬だけ −40%)は拾えません。売ったことにする価格は「確認したときの価格」です。GitHub の実行が遅れると、時間撤退も1時間ちょうどではなく1時間〜1時間20分ほどになります
- 同じ銘柄の仮想ポジションは同時に1つまで(段階が変わって再通知されても、保有中なら買い増ししません)
- 半分を利確したあとも、損切りラインは「購入価格の −40%」のままです
- **1日の上限**(日本時間0時〜24時):仮想購入は平日3回・土日7回まで。その日に決済した仮想売買の損失が 0.4 SOL 相当に達したら、その日はもう仮想購入しません
  - 上限で見送ったときも候補の通知は届き、「本日の上限に達したため見送り」と表示されます
  - SOL 相当額は、DEX Screener の SOL 価格で換算します(`paper_trades.csv` の「損益SOL」列にも記録)
- 記録は `data/paper_trades.csv` に残ります(購入価格・売却の経緯・損益)。ここに入る金額は仮想の $20 だけで、あなたの実際の取引は入りません

## 設定を変える(点数・区切り・基準)

1. GitHub で `config.yaml` を開き、右上の **鉛筆マーク(Edit)** を押す
2. 数字を書き換える
3. **Commit changes** を押す → 次の実行から反映

よく変える項目の例:

| やりたいこと | 変える場所 |
|---|---|
| 候補の区切りを変える | `tiers:` の `small_max`(小の上限)、`medium_max`(中の上限) |
| バンドル率の加点を変える | `scoring:` → `bundle:` の `min` / `max` / `points` |
| リスク大は通知しない | `notify:` → `notify_tiers: [小, 中]` |
| 流動性の基準を1万ドルに | `criteria_a:` → `min_liquidity_usd: 10000` |
| まとめの時刻を朝8時に | `notify:` → `daily_summary_hour_jst: 8` |

> 書き換えるときは、行頭の空白(字下げ)を崩さないでください。崩れるとエラーになります。

## 知っておいてほしい注意点

1. **候補 = 安全、ではありません。** 機械的なチェックを通っただけです。最後は DEX Screener・GMGN・RugCheck の画面を自分の目で確認してください。
2. **GitHub の定期実行は遅れることがあります。** 混雑時は数分〜十数分遅れたり、まれに1回飛んだりします。発行直後の数分を争う用途には向きません。
3. **60日ルール**:公開リポジトリで60日間まったく動きがないと、GitHub が自動実行を止めることがあります。止まっていたら Actions タブで Enable を押してください。
4. **LP の点数**:Meteora DLMM・Raydium CLMM・Orca Whirlpool など「LP トークン」がない仕組みのプールと、pump.fun 卒業前(ボンディングカーブ)は LP 項目の対象外(0点)です。記録の「LP状態」欄に「対象外」と理由が残ります。
5. **上位10件の保有**:流動性プールの口座を除いて計算しています。RugCheck の同じレポートの中で、①RugCheck が AMM と判定した口座 ②プール本体・プールのトークン口座 ③保有数がプール残高と一致 ④保有数×価格がプールのトークン側の金額と一致(予備)、の順に照合します。除外した口座は記録の「除外したプール口座」欄に、割合と照合方法が残ります。ロック口座(Streamflow など)は除外せず、保有として数えます。
6. **見送りの一部は「安全性未確認」**:API の回数を節約するため、次の銘柄は RugCheck を省略して見送りにしています(理由欄に「(拡張機能などの安全性は未確認)」と表示)。
   - 卒業済みで流動性が1.5万ドル未満の銘柄(`rugcheck_skip_below_liquidity`。流動性が増えれば次の再チェックで RugCheck します)
   - pump.fun 卒業前で、進捗・時価総額などの基準で見送りが決まった銘柄
   - pump.fun 卒業前の銘柄は、流動性が低いのが普通なので、流動性による省略の対象外です
7. **LP の状態が分からない場合**(RugCheck に市場情報がない)は、安全側に +1点 します。
8. **RugCheck は無料・キー不要ですが、混雑時は取得できない**ことがあります。その銘柄は次回に回します。
9. **Slack の Webhook URL・API キーを漏らしたら**:Slack は Incoming Webhooks の画面で該当 URL を削除して作り直し、Solana Tracker はダッシュボードでキーを再発行し、GitHub の Secret を更新してください。

## API の呼び出し回数(目安)

15分おき = 1日96回・月約2,900回の実行として計算しています。DEX Screener の新着一覧には1回あたり Solana の銘柄が約35件載っていたので(2026年9月28日時点の実測)、そこから新しく見つかる銘柄を1回15〜35件と仮定しました。

| API | 1回の実行あたり | 月間の合計 | 上限 |
|---|---|---|---|
| DEX Screener | 約15〜18回 | 約4.3万〜5.2万回 | 1分あたり60〜300回(月の上限なし) |
| RugCheck | 約8〜20回(1回40回まで) | 約2.3万〜5.8万回 | 公表なし(0.6秒間隔・1回40回までに制限) |
| Solana Tracker | 約1.5〜2回 | 約4,300〜5,800回 | 無料プランの上限(月10,000回 または 2,500回) |

実際の回数は、毎回の実行ログの最後の行と、1日のまとめ通知の「今月のAPI呼び出し」で確認できます。

## 公開リポジトリと個人情報

- 記録(CSV・state.json)に入るのは、**トークンのアドレス・名前・数値・判定だけ**です。ウォレットアドレス(開発者・保有者・バンドル・インサイダーなど)は保存しません。
- このプログラムはあなたのウォレット・Phantom・取引履歴を一切読みません。購入金額や保有数が記録に入ることはありません。
- `config.yaml` に自分のウォレットアドレスなどを書かないでください(公開されます)。
- GitHub のメールアドレスを隠す:右上のアイコン → **Settings → Emails** → **Keep my email addresses private** にチェック。ブラウザで編集したときの記録に、メールアドレスの代わりに匿名のアドレスが使われます。
- Actions の実行ログも公開されますが、Secrets の値は自動で `***` に伏せられます。

## 困ったとき

| 症状 | よくある原因 |
|---|---|
| Slack に何も来ない | 候補がまだない(正常)/ Secret 名の打ち間違い / Webhook URL の貼り間違い |
| 実行が赤い✕で失敗 | 実行結果 → scan → 赤い段を開いて、表示されたメッセージを確認(相談するときはここをコピー) |
| 「Save records」で失敗 | Settings → Actions → General → Workflow permissions が Read and write か確認 |
| pump.fun の候補が来ない | `SOLANATRACKER_API_KEY` 未設定、または今月の上限に到達(まとめ通知に使用回数が出ます) |
| config を変えたら失敗し始めた | 字下げのズレ。直前の状態に戻すには、ファイル画面の **History** から前のバージョンを確認 |
